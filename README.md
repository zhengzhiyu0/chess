# Maia Coach（iOS 原生国际象棋教练 / 离线 PWA）

> 开发状态（2026-11-04）：Flutter 迁移分支 `codex/flutter-native` 与 `flutter_app/` 暂时废弃，停止维护与功能同步。当前维护版本为 `web/`（Web/PWA 与 Capacitor iOS）。

> iOS 构建：推送后使用 GitHub Actions 的 `Build iOS (unsigned IPA)`（`.github/workflows/ios.yml`），配置为 `79m-full`。手动触发默认及 `ios-v*` 标签触发均采用此配置；产物为 `MaiaCoach-ipa-79m-full`。

- **对手**：Maia-3（官方权重导出为 ONNX，可选 5M / 23M / 79M）。仅在首页用吸附固定档位的进度条选择对手，设置里不重复选择难度；输赢和玩家评级不会自动修改难度。产品档位为 600–2600；低于 600 或高于 2600 的模型输入外推不开放。iOS App 使用预编译 CoreML MLProgram 原生推理，网页版使用 `onnxruntime-web`。
- **教练**：Stockfish 19 完整 NNUE 版，iOS App 使用 C++ 原生多线程，网页版使用 WASM（支持跨源隔离时多线程）；可在设置中切换为小网络的轻量版（秒开、省内存）。
- **功能**：
  - 启动 iOS App / PWA 后自动在后台加载当前设置的引擎。点击开始或继续立即显示棋盘，不再弹出 loading 遮罩；未就绪时仅显示准备文字，棋钟暂停且不调用未就绪的引擎，加载完成后自动恢复。失败时提供不遮挡棋盘的重试入口，等待期间仍可返回首页。
  - 首页对局入口采用紧凑的扁平描边样式，左侧图标、右侧箭头；有未完成对局时突出“继续对局”，否则突出“开始对局”，续局入口保留回合和进度信息。
  - 首页执色使用单行分段选择器：小圆点区分执白、执黑，交错箭头表示随机，淡绿底标识当前选择，不再使用大棋子卡片。
  - 按钮统一采用 12px 圆角、无阴影样式，仅首页对局入口和局外主要操作保留描边；对局内全部按钮及设置内按钮均不显示边框，局内普通工具和未选中的图标按钮使用透明底色，主操作和选中项用淡绿底区分。按下以中心为锚点 `transform: scale(0.97)`，松开恢复，禁用独立 `scale` 和位移；保留必要的尺寸、排布差异和键盘焦点轮廓。
  - 对弈：只保留一种对局，默认纯净，不因坏棋暂停或弹出教学卡片；拟人化走子与思考时间、悔棋和按需提示仍可使用。首页不显示纯净 / 辅助状态或辅助设置入口；仅在对局内「对局辅助」独立开关横向评估条、获胜机会百分比、对手威胁、悬子标记和最佳着法。辅助后台分析不等待用户确认讲解，莉亚文字反馈默认关闭。
  - 对局布局：棋盘与开局 / 着法条保留 10px 间隙，走棋提示靠左且垂直居中；棋盘位置由视口和棋盘尺寸决定，气泡出现、换行和消失不会挤动棋盘，长提示在下方区域滚动。吃子图标为 24px。
  - 手机浏览器地址栏压缩可用高度时，棋盘按高度缩小后仍水平居中，不改变既有垂直定位。自由复盘为左侧评估栏预留对称的右侧空隙，居中的是棋盘本身，进入复盘及后续重绘不再右移；原生与桌面保留原布局。iOS 原生与网页版的自由复盘均不为已隐藏的底部工具栏留出占位；分析滚动区直达屏幕底部，Home 指示条安全区仅作为滚动内容内边距，长讲解和底部按钮可滚动完整显示。
  - 自由复盘的棋盘和分析区受可用列宽约束，长引擎变化行不会撑宽页面或推偏棋盘；讲解文字自动换行，单行引擎变化超出时显示省略号。
  - 箭头提示：普通落子不自动播放威胁 / 保护箭头或逐格铺色特效。“对手威胁”红箭头和“最佳着法”绿箭头由独立开关控制，可同时显示；按棋子路径静态绘制，马使用 L 型路径，支持棋盘翻转与缩放。横向评估条在棋盘上方，白方纯白、黑方深灰（避免与纯黑背景融合），两段按比例填满，数字透明叠加，始终按白方视角显示；获胜机会百分比按用户执色显示，为引擎估算而非实战预测。
  - 箭头描边：主设置中的「箭头描黑边」统一作用于提示、威胁、最佳着法及复盘箭头，默认关闭。开启后箭头完全不透明，彩色主体略细、黑色外描边加粗，箭杆与头部均完整描边；仅改变外观，不开启对局辅助，也不影响计分资格。
  - 赛后讲解：识别将杀、双将、捉双、牵制、串击、闪击、吃掉保护者、困子、杀棋威胁、白吃子、以小换大等战术，用静态交换评估（SEE）和引擎变化说明问题及更好的选择；完整变化演示、人类着法比较和自由试走保留在自由复盘中。
  - 战术识别准确率：`web/test/puzzle-bench.test.ts` 用 3061 道 Lichess 谜题（CC0，`node scripts/build-puzzles.mjs` 生成）统计每类的精确率和召回率，并设置下限防止退化。Lichess 的标签是程序打的、并不完备，所以精确率只是下限。
  - 棋钟：不限时或 3+2 / 5+3 / 10+5 / 15+10 / 30+20，含加秒、超时判负（对方子力不足以将杀时判和）、低时间提醒；Maia 会按剩余时间分配思考时间。
  - 规则：将死、逼和、三次重复、子力不足、50 回合，认输、提和（Maia 依据胜和负概率决定是否接受）。
  - 预走、走子 / 吃子 / 将军 / 易位 / 升变音效与震动反馈（可在设置中关闭）。全部使用成品 MP3：默认“实木棋盘”，另有“轻柔木质 / 柔和落子 / 清脆玻璃”（走子 / 吃子为 [Kenney](https://kenney.nl/assets/impact-sounds) 的 CC0 碰撞录音，其余事件使用 Lichess Standard 音效，见 [web/public/sounds](web/public/sounds/README.md)）。设置中选择即可试听，旧主题自动迁移到对应的录音；对局结束按胜/负/和播放不同音效。
  - **复盘**：赛后分析整局，总复盘保留胜率曲线、准确率、错误标注和学习总结。点击开始复盘进入自由复盘，可在右侧选择「我方关键点」「对方关键点」或「全部着法」，用上一个 / 下一个统一导航；关键点仍指不精确、错误和漏着。问题着法可点「重走」退回上一步重新走；棋盘显示双方引擎最佳、人类常走和上一步应走箭头，可演示引擎变化，也可在任意局面自由试走，试走不会修改实战记录。
  - **复盘布局**：复盘评估条位于棋盘左侧、与棋盘等高，以白方视角显示白色下段和深灰上段；普通对局仍使用原横向评估条。复盘隐藏底部菜单和左右箭头工具栏，查看类型、上一个 / 下一个、重走与回到总复盘保留在右侧控制条中。
  - PGN：导入 / 导出完整变着树、注释、NAG、`[%clk]` 用时和 `[%eval]` 评估；可从任意 PGN / FEN 局面或当前复盘局面开始与 Maia 对弈。
  - 历史与统计：已结束的对局自动保存（最多 300 局），可重新打开复盘；按执色、对手等级分统计胜和负与得分率。
  - 进入复盘自动分析整局，并对当前局面实时多线分析。
  - 双等级比较：总复盘底部「开始复盘」或自由复盘内「比较不同水平的棋手」按需展开。在同一局面并排比较两个 Maia 等级的原始人类着法预测、Stockfish 最佳和行棋方预期得分（胜 + ½ 和）；每列双方使用相同等级，不修改对手难度。共用一个 Maia 实例，省内存模式等待 Stockfish 搜索结束后计算，结果按局面和等级缓存。
  - 玩家棋力评估：无需手动填写起点，新定位统一从 1500、RD 350、波动率 0.06 开始，之后依据纯净标准对局的胜和负及本局对手分自动更新，仅用于棋力记录、人类着法参考与训练推荐；不会自动调难。赛后累计周期进度，每满 10 局统一更新，不受准确率或复盘进度影响；辅助练习不计分，无辅助正式局自己走满 3 步后中途离开按认输计，无额外加罚。
  - 谜题训练：内置 50000 道 [Lichess 谜题](https://database.lichess.org/#puzzles)（CC0，`node scripts/build-puzzle-db.mjs` 生成到 `web/public/puzzles/`），独立的谜题等级分；进入后先到类目页，可选综合练习或按题型（基础战术 / 进阶战术 / 将杀 / 对局阶段）练习，并根据等级分（谜题少于 20 题时用对局等级分）、各题型正确率和错题本里的错误类型推荐优先练的 3 个题型；网页版作为离线包下载，iOS App 内置。
  - 错题本与训练闭环：复盘分析完成后，自己的错误、错失良机和漏着自动收录并按错误类型归类（如“被对方捉双”“错过将杀”），间隔重复重练，连续答对 3 次算掌握；赛后本地总结最多列出 3 个重点问题，关联错误类型、错题重练和对应题型谜题，并给出值得保留的好棋、下一次检查点与近 30 天训练建议。练习结果更新错题掌握度；统计最常犯的错误及趋势。
  - 数据备份：设置、等级分、历史、错题本、谜题进度导出为一个 JSON 文件（iOS 用系统分享面板，网页下载或分享），网页版与 App 互相导入，默认按 ID 合并去重；也可导出全部对局为 PGN。导入 PGN 支持多局文件。
  - iOS 启动诊断：在「设置 → 导出本次启动日志」分享 TXT。日志合并前端和原生记录，包含 CoreML 请求/排队/模型加载/首次探针预测、模型复用或失败，以及 Stockfish 的启动握手、Threads/Hash 就绪屏障耗时。Stockfish 初始化可能包含 NNUE 加载，但不把握手耗时冒充为单独 NNUE 耗时。记录按单调时钟计时，不保存完整棋谱或模型输入；只保留当前进程的有限条记录，排查首次加载请在同一次打开中导出，勿先强退应用。
  - 采样诊断：设置中解释原始预测概率、temperature 调整后的实际选中概率与预期得分的区别。对弈 Top-P 固定为 1，不增加滑块。诊断默认关闭，保存开启后只捕获成功落子的 Maia 决策，保存在本机、不上传；含双方等级、模型、落子前 FEN、参数、原始 / 实际概率、所选走法、推理耗时与行棋方 WDL。最多最近 10 局且 UTF-8 JSONL 不超过 8 MiB，超限先移除旧决策，浏览器容量不足会明确报错但不影响落子；可导出离线 HTML 或 JSONL，清除不删除棋谱。诊断独立于普通备份与本次启动日志。
- 首次加载后可**完全离线**使用：Service Worker 会缓存全部文件；每次构建会给 `sw.js` 注入新版本号，部署后自动清理旧文件，并在页面上提示“有新版本”。

## 玩家棋力评估与固定对手难度

- **两个数值**：`playerElo` 是玩家自动定位的本地棋力估计，`elo` 是手动选择的下一局 Maia 固定难度。玩家无需填写 Elo，设置仅保留“重新定位棋力”；重置会回到 1500 / RD 350 / σ 0.06 并清空本周期。首个周期完成前显示“棋力定位中”和进度，1500 只作内部先验。训练推荐使用玩家估计，不随对手档位变化。
- **评级模型**：采用 Glicko-2，维护玩家分数、评级偏差 RD 和波动率 σ，按作者 2022 年规范实现转换、对手 RD 权重和波动率迭代求解。σ 初始 0.06、τ 为 0.5；每 10 局独立计分对局作为一个评级周期，周期内分数、RD 和波动率保持不变，第 10 局结束后用周期初状态统一计算全部结果。未满周期的结果保存到设置、对局快照和备份；训练局不占周期名额。Maia 档位作为固定对手分（对手 RD 0），预期得分率在 Glicko-2 尺度上计算，和棋记 0.5；准确率和连胜负计数不参与计算。分数、RD 与波动率在计算、存档及备份中保留完整精度；只在界面和 PGN 显示时取整，不施加玩家分数上下限或 RD 人工上下限。定位初始 RD 350。不按日历补算空周期，训练局也不推进评级周期。作者建议每周期通常至少 10–15 局；本项目采用 10 局；具体对手强度和预测质量仍需用真实对局验证。若实际棋力离默认先验较远，批量更新可能需要多个周期，不能只凭第一个周期就宣称估分准确。
- **估计与选档**：个人页及赛后显示估分和向外取整的 `估分 ± 2RD` 参考范围；少于 10 局独立计分或 RD > 100 时标为暂定。该范围依赖模型假设，并非真人 Elo 的保证区间。新安装默认对手 Maia 600。首次可跳过“刚入门 / 下过一些 / 经常下棋”，仅建议 600 / 1000 / 1500，不修改 Glicko-2 初值。定位中同档最近连续两局全胜/全负时建议升/降一档；未完成定位不根据 1500 先验推荐对手，低置信度时优先参考近期结果。稳定后推荐最接近估分的档位；采用建议需要点击确认，只影响下一局。一直对战 Maia 600 也可以估到 600 以上，例如长期得分率 75% 对应约 791；对手过弱时信息较少，应挑战邻近档位。
- **难度固定**：对手档位为 600 / 800 / 1000 / 1200 / 1400 / 1500 / 1600 / 1800 / 2000 / 2200 / 2400 / 2600，只有用户主动选择才会变化；已移除自动调难开关和逻辑。玩家估计不受对手档位范围限制；只有传给 Maia 的条件分限制在模型支持的 600–2600，不修改存储的评级状态。旧版 0 / 300 对手设置迁移为 600，历史和进行中对手分不变。
- **整局锁定**：开局保存双方分数、RD、波动率、连续结果、独立计分局数、Maia 模型与随机性；局中修改设置不改变当前局，续局使用原快照。赛后立即保存周期进度，满 10 局统一更新，不依赖 Stockfish 或复盘成功；后续分析不改分。PGN 分别导出双方分数。
- **辅助练习**：评估条和胜率显示不影响计分。实际展示提示、最佳着法、威胁、受攻击棋子提示或局中分析，以及任何一次悔棋，使本局转为训练。仅打开开关、未展示信息不影响计分；曝光记录跨悔棋、删除分支及关闭开关保留。辅助局无论胜负均不更新分数、RD、波动率、连续结果或计分局数；赛后复盘不影响已结算结果。导入棋谱、非标准起始局面、随机性不为 1 的对局也不计分。落子后的着法评价徽章保持为反馈，不单独排除计分。本项目的“独立计分”允许上述局面数值反馈，不能等同于外部平台的无辅助对局。
- **旧数据与备份**：保留已有合法评级状态；缺失玩家分数、RD 或波动率分别采用 1500、350、0.06，不将对手档位当玩家分数，也不按历史局数虚构 RD；已结算历史保留原分数和旧算法说明，不重算。“重新定位棋力”统一从官方建议初值开始。旧教练模式辅助资格仍保留。备份合并按较多累计计分局数同步包括独立局数在内的评级状态，保留本机固定对手档位。
- **参考与边界**：实现参考 [Glickman 的 Glicko-2 原始设计与算例](https://www.glicko.net/glicko/glicko2.pdf)，并以官方三对手算例回归分数、RD、波动率；[Lichess](https://lichess.org/page/rating-systems) 也使用 Glicko-2。数学核心支持一个周期内多个不同 RD 的对手及空周期，产品采用上文披露的 10 局周期、固定机器人锚点配置。借鉴 [Duolingo 对 Elo 的官方说明](https://blog.duolingo.com/what-is-an-elo-rating-in-chess/)中按对局结果更新、分数只适用于本对手池的原则；其未公开辅助折算公式，训练资格为本项目的产品规则。[Maia-3 官方模型说明](https://huggingface.co/UofTCSSLab/Maia3-5M/blob/main/README.md)将其定位为按玩家分数预测人类着法，不能直接将条件档位当作已校准的对战实力。后续应针对模型版本、档位、采样参数和用时，收集已知等级玩家的独立完整对局来标定对手分及不确定度，再用留出对局检验得分率校准和参考范围覆盖率。现有 Maia 档位未用真人对战标定；这些统计更新不等同于 FIDE、Lichess 或 Duolingo Elo，也不证明真实 Maia 的校准准确度。

## 拟人评测与设计参考

- 从 `web/` 运行 `npm run bench:human -- --smoke` 验证真实模型链路；`npm run bench:human -- --out reports/human-bench` 生成三种模型的描述性报告。需 Node ≥22.18，无新增 npm 依赖；详见 [评测方法、数据来源与复现命令](web/scripts/HUMAN-BENCH.md)。
- 真人下一着指标使用固定来源、哈希与 CC0 声明的 12 局 Lichess 公开实战，而不是谜题最优解或模型自对弈；另用固定 seed 的真实模型开局采样测量变化、重复率、熵与开局家族。默认无历史输入，与产品一致，`--history` 是明确分开的研究模式。
- 已生成 [三模型基线报告](web/reports/human-bench-baseline.md)及[逐项 JSON 证据](web/reports/human-bench-baseline.json)：96 个真人局面，每模型每策略 24 条、最多 8 回合开局。数据是早期便利小样本，可能与训练集重叠，不是独立 held-out 基准，不能据此宣称普适拟人准确率或 Elo。
- 采样研究设计、双等级比较与概率说明参考 Dash1971 的 [Mobile Maia](https://github.com/Dash1971/maia-chess-android) 和 [采样研究](https://github.com/Dash1971/mobile-maia-research/blob/a2d90a94aac930fe17109f5e7e1b2e351c18b4fd/studies/maia3-sampling/REPORT.md)。对方采用 AGPL-3.0-only、核心为 Dart；本次复用本项目既有 TypeScript 编码器、采样器、Maia 和分享接口独立实现，没有复制其 Dart/Python 代码、报告图表或处理后数据。公开方法参考不冒称直接代码移植，原上游许可不变。

## 安装到 iPhone（无需开发者账号）

PWA 和 Service Worker 要求 **HTTPS**（localhost 除外），手机访问电脑上的 `http://192.168.x.x` 时无法离线安装。推荐方式：

1. **GitHub Pages**
   - 推送到 GitHub 的 `main` 分支后，[deploy.yml](.github/workflows/deploy.yml) 会自动构建并部署（需在仓库 Settings → Pages → Source 选 **GitHub Actions**）。
   - 也可以手动把 `web/dist/` 的内容推送到 `gh-pages` 分支。
   - 单文件均小于 100MB，模型已分片，Stockfish wasm 约 95MB。
   - 部署后用 iPhone Safari 打开网址，点击“分享 → 添加到主屏幕”。
2. 其他任意 HTTPS 静态托管（Cloudflare Pages、Netlify 等）也可以。
3. 首次打开后会自动加载当前设置的模型和 Stockfish，并下载离线包；离线包就绪后即可断网使用。

说明：

- 静态托管通常不能设置 COOP/COEP 头。`sw.js` 会在响应中注入这两个头；首次接管尚未隔离的顶层主页时，页面最多自动刷新一次以启用多线程，不中断已进入的对局。网页版离线包在支持多线程时同时缓存当前 Stockfish 版本的单线程后备，避免多线程启动失败后无法离线使用。
- iPhone 首次启动时默认使用 **5M 模型 + 省内存模式 + Stockfish 轻量版**：轻量版足够小，两个引擎可同时常驻，不必反复重新加载；关闭轻量版后，省内存模式会在切换对弈/复盘时卸载另一个引擎。
- Maia 推理后端可选 WebGPU（模型已针对 WebGPU 导出，结果与 WASM 一致）；若 GPU 推理结果异常会自动回退到 WASM。
- 79M 模型（312MB）在 iPhone 上可能因内存不足被系统终止，请谨慎使用。
- iOS 可能清理长期未使用的 PWA 缓存，清理后联网打开一次即可恢复。

## 打包为 iOS App（iOS 17+，免费 Apple ID 自签）

不需要 Mac 和付费开发者账号：由 GitHub Actions 的 macOS runner 编译未签名 IPA，再在 Windows 上签名安装。

1. 在 GitHub 仓库的 Actions 页面运行 **Build iOS (unsigned IPA)**（[ios.yml](.github/workflows/ios.yml)），也可以推送 `ios-v*` 标签触发。手动运行时可选择 `all`（全部引擎）或 `79m-full`（仅 Maia 79M + Stockfish 满血版）。
2. 运行完成后下载对应的 `MaiaCoach-ipa-*` artifact，解压得到 `MaiaCoach.ipa`。
3. 用 [Sideloadly](https://sideloadly.io/)（或 AltStore）连接 iPhone，使用自己的 Apple ID 签名并安装。
4. iPhone 上打开「设置 → 通用 → VPN 与设备管理」，信任该开发者；iOS 17 及以上还需开启「设置 → 隐私与安全性 → 开发者模式」。

说明：

- 免费 Apple ID 签名的 App **7 天后过期**，需要重新签名（棋局和设置保留）。AltStore 可以在同一 Wi-Fi 下自动续签。
- App 内的引擎**全部原生实现，不使用 WebAssembly**（[native-plugins/maia-native](web/native-plugins/maia-native)）：
  - **Stockfish 19**：C++ 源码直接编进 App（-O3 + ThinLTO），原生多线程 + ARM NEON/dotprod。**满血版**（完整 NNUE）和**轻量版**（小网络）都已预装，在「设置 → Stockfish 版本」中切换。默认 2 线程（性能核数量），避免发热。切换版本时旧实例的 Hash 缩至 1MB，重新启用时恢复设定值；进入后台由原生通知兜底停止搜索。
  - **Maia-3 5M / 23M / 79M**：CoreML 原生推理，预装 fp16 计算的 `.mlmodelc`；主干矩阵使用 INT8 权重量化，GAB 注意力偏置生成器保留 fp16，避免误差跨层累积。CI 从固定 batch 1 的 native ONNX 转换模型：将 Constant 提为 initializer、把 GAB 的 Einsum 等价展开为矩阵乘法，并统一 MIL 编写精度以避免 LayerNorm 类型冲突。三种编译模型各须通过 7 个现有棋局样本的 ONNX 对照（合法走法概率和胜和负概率最大误差均不超过 0.02），通过后才进入 App bundle；iOS 不再依赖 ONNX Runtime，也不再生成或清理 ORT 模型缓存。构建失败时保留 CoreML/Xcode 日志 artifact 和错误摘要。
  - **关键事件文字提示**：普通对弈中由莉亚头像显示简短的战术和棋力反馈；其他教练头像资源保留在项目内，当前不参与选择或运行时逻辑。
  - 全部预装，无需下载，完全离线可用；App 内没有下载按钮和离线包管理。「设置 → 环境信息」显示当前引擎的实际运行方式。
- App 的对弈界面与手机网页版一致：菜单在顶部，提示/悔棋/教练在“我”的信息栏里。点自己的头像（或「设置 → 我的头像」）可换成预设头像（不再读取相册，避免申请照片权限）。iOS 音效由 AVAudioPlayer 直接播放内置 MP3，通过应用内音效开关控制，使用媒体音量，允许与其他应用音频混音；每次播放重新激活音频会话，进入后台或被电话中断时停止旧声音，回来后只播放新事件。70 毫秒内的重复落子音效会被过滤。
- 本地准备 iOS 工程：`cd web && npm run build:native`，依次执行构建、生成 `dist-native/`（[prepare-native.mjs](web/scripts/prepare-native.mjs)：去掉所有 wasm，下载并校验 NNUE 网络，拼接 `native-models/` 中的 ONNX 中间文件）、`cap sync ios`；随后在 macOS 按 [ios.yml](.github/workflows/ios.yml) 安装 Python 转换依赖，执行 `python scripts/compile-coreml.py`，完成模型转换、量化、编译和数值对照，再用 Xcode 构建。编译产物按源 ONNX 内容缓存，最终 bundle 不保留 Maia ONNX。Xcode 工程位于 `web/ios/`。
- 原生 Stockfish 可以脱离 Xcode 单独测试：`sh web/native-plugins/maia-native/stockfish/test/build_smoke.sh web/.cache/nnue`（CI 也会在 arm64 macOS 上跑这一步）。
- Stockfish 以 GPL-3.0 发布，源码见 [stockfish/](web/native-plugins/maia-native/stockfish)。
- 私有仓库使用 macOS runner 会按 10 倍分钟数计费，公开仓库免费。

`79m-full` 是固定引擎构建：设置页不显示 Maia 模型和 Stockfish 版本切换；旧设置、备份和未完成对局中的引擎选择也会归一化为 Maia 79M / Stockfish 满血版。该 profile 的 App bundle 不包含 5M、23M 或 Stockfish lite 的原生资源。

## Maia 完整对局实验

从 `web/` 运行 `node scripts/maia-match.mjs --model-root public/models --pairs 600:800,800:1000,600:1500 --repeats 6 --max-plies 1000 --out ../tmp/maia-match`。fp16 对照用 `--model-root native-models` 和不同输出路径。每组 6 对交替执色，共 12 局；79M 真实 ONNX CPU，temperature=1、topP=1、仅当前 FEN、标准初始局面、不限时，与产品不限时配置一致。按产品 `terminalOf` 判断终局，不使用开局库、引擎裁判或自动认输；达到上限为未完成，不记和棋。每盘保存 PGN、UCI、seed、模型/实现哈希和终局原因，逐局检查 PGN 可合法回放。输出 JSON/MD/PGN，支持相同配置断点继续及扩大重复数。模型间对战仅验证档位相对表现，不能校准真人 Elo；fp16 ONNX 不替代 iPhone CoreML 实机验证。

本次探索结果与全部棋谱：[72 盘报告](web/reports/maia-match-20261106/README.md)。仅覆盖三组对阵，尚未覆盖全部档位或时限，也未据此修改对手分数。
