# 79M 档位完整对局探索实验

2026-11-06，Windows ONNX CPU；fp32 与 iOS 来源 fp16 各 36 盘，总计 72 盘，全部按产品规则终局。每组 6 对交替执色，采用相同随机种子的配对设计；这些棋局并非 72 个独立真人样本。

| 对阵（高档对低档） | fp32 胜/和/负 | 得分率 | fp16 胜/和/负 | 得分率 |
|---|---|---|---|---|
| 800 对 600 | 6/2/4 | 58.3% | 8/2/2 | 75.0% |
| 1000 对 800 | 7/3/2 | 70.8% | 8/2/2 | 75.0% |
| 1500 对 600 | 9/2/1 | 83.3% | 8/3/1 | 79.2% |

三组高档在本样本中的得分率均高于 50%，但每配置每组仅 12 盘，不证明总体强度顺序、分差或统计显著性。fp16 与 fp32 的随机路径对浮点差异敏感；不能把胜负差异解释为转换后的确定性棋力变化。低档相邻档位证据尤其有限。没有据此重标产品档位，也没有将结果转换为真人 Elo。

只评测产品“不限时、temperature=1、topP=1、history=off”配置。没有测试不同棋钟；没有在 iPhone 上验证 CoreML 行为，也没有覆盖全部 600–2600 档位。没有机器人对真人的标定数据。

每模型同名 JSON 含运行配置、模型 SHA、每盘运行时实现 SHA、完整 UCI/PGN、最终 FEN、终局原因和分执色统计；PGN 均逐盘合法回放核验。扩样期间脚本只调整了断点配置兼容和逐盘元数据，棋局生成逻辑未更改。后续脚本格式调整后哈希不同，因此不得使用旧输出路径断点续跑；请选新路径。原始报告保留实际运行时的哈希，不改写为后续脚本哈希。

复现入口：`web/scripts/maia-match.mjs`，具体命令见项目 README。复现随机流不保证不同 CPU/ONNX Runtime 的最后位浮点完全相同。
